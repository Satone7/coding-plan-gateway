# Technical Design: Coding Plan Gateway

**Branch**: `001-coding-plan-gateway` | **Date**: 2026-03-20 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/001-coding-plan-gateway/spec.md`

## Summary

A gateway service that provides unified API access to multiple AI coding plan subscriptions. It routes requests to appropriate providers based on model availability and quota, exposing OpenAI and Anthropic compatible APIs. The design prioritizes extensibility for future features: database storage, multi-user support, Web UI, and TUI onboarding.

---

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode) on Node.js 20+ LTS
**Primary Dependencies**: Fastify 4.x, Vitest, Zod (validation), MSW (mocking)
**Storage**: YAML/JSON files (current), PostgreSQL with Drizzle ORM (future migration path prepared)
**Testing**: Vitest + MSW for unit/integration, real provider tests for E2E
**Target Platform**: Linux server, local Docker deployment
**Project Type**: Single (backend API with future Web UI extension)
**Performance Goals**: <50ms routing overhead (p95), streaming passthrough <10ms latency
**Constraints**: <200MB memory, single-user local deployment (current), no external network exposure
**Scale/Scope**: 10+ coding plans, 100+ concurrent requests, 99.9% availability

### Key Components

| Component | Responsibility | Extensibility |
|-----------|---------------|---------------|
| `PlanRepository` | Storage abstraction | Interface allows swapping file → database |
| `QuotaManager` | Track usage per plan | Event-based for future webhooks |
| `PlanSelector` | Choose best plan | Pluggable selection strategies |
| `RequestProxy` | Forward to upstream | Interceptor hooks for plugins |
| `CircuitBreaker` | Handle failures | Configurable failure thresholds |
